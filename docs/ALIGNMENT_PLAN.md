## B. 순차 실행 계획 (위에서부터)

### B-1. 조직모델·용어 정렬  ⚠️ 기반 변경(고위험)
- 제안 3그룹: **운영(3S)=본사 · 요청(라이프사이언스) · 이용(대리점·병원창고)**.
- 현행 4역할(HQ/WAREHOUSE/HOSPITAL/SUPPLIER)에 **'요청' 주체(라이프사이언스)가 없음** — 병원이 직접 사용분 등록.
- **안전 설계(권장·additive)**: `OrgType`에 `LIFE`(라이프사이언스=요청) **추가**(기존 값 유지 → 데이터·정책·시더 무파손). 라벨/그룹 레이어로 3그룹 표기.
  - 영향: `OrgType`(+case/label), `EnsureRole`, Policies, Global Scopes, `config/menu.php`, 시더(LIFE org/user), 대시보드, 방금 만든 매뉴얼.
  - 검증: `php artisan test`(103↑) 무회귀 + LIFE 계정 권한 스코프 테스트 추가.
- 결정필요: '요청' 흐름을 **물품요청→출고**로 볼지(현행 출고지시와 통합) 여부.

### B-2. 반납 전용 화면/서비스  ⚠️ 재고 원장 의미 결정
- 흐름: 반납 등록(라이프/병원) → 지역담당 배송 → 3S 수령확인 → 본사 재고 +1 복귀.
- 설계: `ReturnService`(StockService 단일 진입점 사용) — 병원 `RETURN_HOSPITAL(−)` + 창고 복귀(+) **원자적 트랜잭션**. 상태(등록/배송/수령/완료) 테이블 신설(`returns`/`return_items`).
- 결정필요(미정#4): 반납 시 **유효기간 잔여 기준**(재배치 가능 조건).
- 검증: 반납 확정 후 병원↓·창고↑ 원장 합치 Pest.

### B-3. 소급·사후 사용 등록
- 사용 단계에서 **직접 사용확정 등록**(사전 요청·출고 없이) → 재고 차감 + 매출 인식 동시.
- 설계: `UsageController` 소급 등록 액션 + `UsageApprovalService` 재사용(재고 차감/정산). 마감월 차단 규칙 준수.
- 결정필요(미정#3): 소급건의 승인 절차(자동 승인 vs HQ 승인).

### B-4. 30일 무응답 마감·리마인더 스케줄러
- 출고(DELIVERED) 후 N일(기본 30, 미정#1 확정 필요) 내 사용/반납 확정 없는 건 →
  요청(라이프)에게 리마인더 Notification(NOTICE 인프라 재사용) + **강제 마감** 옵션.
- 설계: `Console/Commands/UsageCloseReminderCommand`(`usage:close-reminder`) + Scheduler 등록.
- 검증: 30일 경과 더미 → 알림 생성 Pest.

### B-5. 채널별 매출 + 상품분석 + QR 라벨
- **채널**: 사용분/정산에 `sales_channel`(GPO/Direct/3PL/수술/온라인) 필드 추가 → 채널별 매출 리포트.
- **상품분석**: 품목별 사용량·회전율·매출 집계 리포트 화면.
- **QR 라벨**: 출고 확정·대량입고 시 LOT/유효기한 QR 라벨(PDF/이미지) 자동 생성(예: `endroid/qr-code` + PDF).
- 결정필요(미정#6): 매입가 리포트 노출 범위.

### B-6. 안전재고 자동추천 고도화
- 창고별 차등 + **최근 3~6개월 사용량 × 안전계수** 자동 산출 추천. 현행 `safety_stocks`(병원×품목) 확장.

### B-7. 외부연동/배포 (결정 필요 — 비용·인프라)
- **카카오 알림톡**: 별도 사업자 채널·발신프로필·템플릿 심사 필요. 현행 FCM 병행 or 대체 결정.
- **PWA**: 이미 네이티브 APK 앱 존재. PWA(manifest+service worker) 추가 여부 결정.
- **Supabase RLS**: 현행 Laravel Global Scope로 동등 구현 → **전환 비권장**(사양의 취지는 충족).
