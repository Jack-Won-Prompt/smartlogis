# SmartLogis 앱 — 운영 배포 및 업데이트 테스트

## 현재 배포본: **v1.1.0 (versionCode 3)**

| 파일 | 크기 | 용도 |
|---|---|---|
| `smartlogis-1.1.0-arm64.apk` | 36.2MB | **권장** — 2017년 이후 기기 대부분 |
| `smartlogis-1.1.0-universal.apk` | 82.7MB | 기종을 모를 때 · arm64 가 안 될 때 |
| `smartlogis-1.1.0-arm32.apk` | 32.4MB | 2016년 이전 32비트 기기 |

v1.1.0 에 들어간 것: 재고 실사 · 메세지(사진 전송 포함) · 배송 처리(지시서 QR → 인수 사진·서명)
· 출고 부분 피킹 · 목록 병원 필터.

전 버전 동일한 릴리스 키로 서명(SHA-256 `0912D9C7…86F2`)되어 **덮어쓰기 업데이트가 됩니다.**
체크섬은 `SHA256SUMS.txt` 와 설치 페이지 하단에 있습니다.

## 게시 방법

```bash
flutter build apk --release --split-per-abi
flutter build apk --release                  # universal
cp build/app/outputs/flutter-apk/app-arm64-v8a-release.apk   dist/smartlogis-<버전>-arm64.apk
cp build/app/outputs/flutter-apk/app-armeabi-v7a-release.apk dist/smartlogis-<버전>-arm32.apk
cp build/app/outputs/flutter-apk/app-release.apk             dist/smartlogis-<버전>-universal.apk

python dist/publish.py <버전>       # 설치 페이지·체크섬 갱신 + public/app 복사
```

> `publish.py` 를 만든 이유: 설치 페이지에 버전·크기·해시를 손으로 적어 두었더니
> **1.0.1 을 올리고도 페이지는 1.0.0 을 가리키고 해시는 옛 값이 남아 있었습니다.**
> 파일에서 읽어 만들면 어긋날 수 없습니다.

게시 후 서버 `.env` 의 버전 정보를 올려야 기존 설치본이 업데이트 알림을 받습니다.

```
APP_ANDROID_LATEST_VERSION=3
APP_ANDROID_LATEST_VERSION_NAME=1.1.0
APP_ANDROID_DOWNLOAD_URL_ARM64=<설치 페이지 도메인>/app/smartlogis-1.1.0-arm64.apk
APP_ANDROID_RELEASE_NOTES="변경사항1|변경사항2"
```
그리고 `php artisan config:clear`.

### 검증 완료 (에뮬레이터 Pixel 5 · Android 14)

업데이트 전 과정을 **끝까지 실행해 확인**했습니다.

| 단계 | 결과 |
|---|---|
| 버전 확인 → 안내 표시 | ✅ "새 버전이 있습니다 v1.0.1" + 변경사항 |
| 이미 받아 둔 파일 재사용 | ✅ 재다운로드 없이 곧바로 설치 단계로 |
| 설치 권한 없음 감지 | ✅ 오류가 아닌 전용 안내 + [설정 열기] |
| 설정 화면 직행 | ✅ `ManageAppExternalSourcesActivity` 실행 |
| 권한 허용 후 설치 | ✅ 시스템 설치 화면 → "Do you want to update this app?" |
| 실제 설치 | ✅ `versionCode=1 → 2`, `versionName=1.0.0 → 1.0.1` |
| 재실행 | ✅ 안내가 더 이상 뜨지 않음 |

불필요 권한도 제거됐습니다. 매니페스트 최종 권한은 **4개뿐**입니다 —
`INTERNET` / `ACCESS_NETWORK_STATE` / `CAMERA`(바코드) / `REQUEST_INSTALL_PACKAGES`(업데이트).
범용 파일 열기 플러그인이 끌고 오던 사진·동영상·오디오·저장소 접근 권한은 모두 사라졌습니다.

## 1. 서버에 올릴 것

### 1-1. 코드 (git → `deploy.sh`)

```
config/mobile.php                                    # 신규 — 버전/다운로드 URL 설정
app/Http/Controllers/Api/V1/AppVersionController.php # 신규 — GET /api/v1/app/version
routes/api.php                                       # 수정 — 위 라우트 등록
public/app/index.html                                # 신규 — 설치 안내 페이지
public/app/install-qr.png                            # 신규 — 설치 QR
public/app/SHA256SUMS.txt                            # 신규
public/app/.htaccess                                 # 신규 — APK MIME + 정적 서빙
.gitignore                                           # 수정 — /public/app/*.apk 제외
```

```bash
git add config/mobile.php app/Http/Controllers/Api/V1/AppVersionController.php \
        routes/api.php public/app/index.html public/app/install-qr.png \
        public/app/SHA256SUMS.txt public/app/.htaccess .gitignore
git commit -m "모바일 앱 버전 확인 API + 설치 페이지"
git push origin master
# 운영 서버에서
bash deploy.sh
```

### 1-2. APK (직접 업로드)

APK 6개는 git 에 넣지 않습니다(합계 약 300MB). 운영 서버 `public/app/` 로 직접 올리세요.

```bash
scp dist/*.apk 사용자@smartlogis.co.kr:/운영경로/smartlogis/public/app/
```

### 1-3. `.env` (운영 서버에서 직접 편집)

**아직 latest_version 을 올리지 마세요.** 1.0.0 을 먼저 배포하고, 사람들이 깔고 난 뒤에
2로 올려야 업데이트가 뜹니다.

```dotenv
# 1단계 — 최초 배포 시점
APP_ANDROID_LATEST_VERSION=1
APP_ANDROID_LATEST_VERSION_NAME=1.0.0
APP_ANDROID_MIN_VERSION=1
APP_ANDROID_DOWNLOAD_URL=https://smartlogis.co.kr/app/smartlogis-1.0.0-universal.apk
APP_ANDROID_DOWNLOAD_URL_ARM64=https://smartlogis.co.kr/app/smartlogis-1.0.0-arm64.apk
APP_ANDROID_DOWNLOAD_URL_ARM32=https://smartlogis.co.kr/app/smartlogis-1.0.0-arm32.apk
APP_ANDROID_INSTALL_PAGE=https://smartlogis.co.kr/app/
APP_ANDROID_RELEASE_NOTES=""
```

```bash
php artisan config:cache
```

> **주의:** `.env` 값에 공백이 있으면 **반드시 큰따옴표**로 감싸세요.
> 안 그러면 Laravel 이 `.env` 전체를 파싱하지 못해 **사이트 전체가 500** 이 됩니다
> (실제로 테스트 중 겪었습니다).

## 2. 업데이트 테스트 절차

### 2-1. 준비 — 1.0.0 설치

1. 휴대폰에서 `https://smartlogis.co.kr/app/` 접속 (PC 라면 QR 스캔)
2. **일반 스마트폰(권장)** 눌러 설치
3. 로그인해서 정상 동작 확인

### 2-2. 업데이트 트리거

운영 `.env` 를 2단계로 바꾸고 캐시 재생성:

```dotenv
APP_ANDROID_LATEST_VERSION=2
APP_ANDROID_LATEST_VERSION_NAME=1.0.1
APP_ANDROID_MIN_VERSION=1
APP_ANDROID_DOWNLOAD_URL=https://smartlogis.co.kr/app/smartlogis-1.0.1-universal.apk
APP_ANDROID_DOWNLOAD_URL_ARM64=https://smartlogis.co.kr/app/smartlogis-1.0.1-arm64.apk
APP_ANDROID_DOWNLOAD_URL_ARM32=https://smartlogis.co.kr/app/smartlogis-1.0.1-arm32.apk
APP_ANDROID_RELEASE_NOTES="업데이트 기능 검증용 빌드"
```

```bash
php artisan config:cache
curl "https://smartlogis.co.kr/api/v1/app/version?version_code=1&abi=arm64-v8a"
# update_available: true 확인
```

### 2-3. 휴대폰에서 확인

앱을 **완전히 종료했다가 다시 실행**하거나, 백그라운드로 보냈다 30분 뒤 복귀하면
(테스트라면 종료 후 재실행이 빠릅니다) 화면 위에 업데이트 안내가 뜹니다.

확인할 것:

| 단계 | 기대 동작 |
|---|---|
| 앱 실행 | "새 버전이 있습니다 v1.0.1" + 변경사항 목록 |
| **아무 화면에서나** | 대시보드·재고·스캐너 어디서든 동일하게 뜸(전역 오버레이) |
| [지금 업데이트] | 진행률 표시(`12.3 / 35.1MB`) |
| 최초 1회 | "설치하려면 한 번만 권한을 켜 주세요" → [설정 열기] → 허용 → [권한을 켰습니다 · 설치하기] |
| 이후 | 시스템 설치 화면 → [설치] → 완료 |
| 재실행 | 업데이트 안내가 더 이상 뜨지 않음 |

## 3. 알아 둘 제약

- **완전 무인 설치는 불가능합니다.** 마지막 [설치] 확인은 안드로이드가 반드시 사용자에게
  받습니다(MDM 기기관리자/시스템 앱이 아닌 한). 자동화되는 범위는 **감지 → 내려받기 →
  설치 화면 띄우기** 까지입니다.
- 최초 1회는 사용자가 "출처를 알 수 없는 앱 설치"를 켜야 합니다. 앱이 해당 설정 화면으로
  **바로 보내 줍니다**(설정 앱에서 헤매지 않도록).
- 확인 주기는 앱 시작 + 백그라운드 복귀, **30분에 1회**로 제한했습니다.

## 4. 강제 업데이트가 필요할 때

API 계약이 깨지는 변경(재고·정산 로직 등)을 배포할 때만 `MIN_VERSION` 을 올립니다.

```dotenv
APP_ANDROID_MIN_VERSION=2   # versionCode 2 미만은 앱 사용 차단
```

이러면 구버전 사용자는 **[나중에] 버튼이 사라지고 뒤로 가기도 막혀** 업데이트해야만
앱을 쓸 수 있습니다. 평상시에는 `MIN_VERSION` 을 올리지 마세요 — 매 배포가 강제가 되면
수술실·창고에서 급한 작업 중에 앱이 막힙니다.

## 5. 다음 버전 배포 순서

```bash
# 1) pubspec.yaml 의 version 을 올린다 (+뒤 versionCode 는 반드시 증가)
#    예: 1.0.1+2 → 1.0.2+3
flutter build apk --release
flutter build apk --release --split-per-abi

# 2) APK 를 운영 public/app/ 에 업로드
# 3) .env 의 LATEST_VERSION / VERSION_NAME / DOWNLOAD_URL_* 갱신
# 4) php artisan config:cache
```

versionCode 를 올리지 않으면 기기가 "이미 최신"으로 보고 설치를 거부합니다.

## 6. 서명 키 (재확인)

```
키스토어 : smartlogis_app/android/smartlogis-release.p12
비밀번호 : smartlogis_app/android/key.properties
SHA-256  : 09:12:D9:C7:85:7C:96:3A:B8:85:F7:F9:C1:61:89:CF:
           93:5A:7C:F3:F3:69:35:94:80:96:66:ED:AF:C5:86:F2
```

**잃어버리면 업데이트를 배포할 수 없습니다.** 다른 키로 서명한 APK 는 기존 앱 위에
설치되지 않아 전 직원이 앱을 지우고 새로 깔아야 합니다. 비밀번호 관리자 + 오프라인
두 곳에 백업하세요. 두 파일은 `.gitignore` 에 있어 저장소에 올라가지 않습니다.
